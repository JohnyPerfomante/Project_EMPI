# Версія для GitHub і перенесення

Ця копія містить актуальні вихідні файли, включно зі змінами, які ще не були закомічені в початковому проєкті. Код застосунку, міграції, банк питань, тести, презентація та ілюстрована інструкція DOCX перенесені повністю. Оригінальний проєкт і його Docker-томи збережені окремо.

## Завантаження на GitHub

1. Розпакуйте `Проект_ЕМПІ_GitHub.zip` і відкрийте термінал у папці проєкту.
2. Створіть на GitHub порожній репозиторій, наприклад `osvitnii-protses`. Під час створення не додавайте README, ліцензію чи `.gitignore`, оскільки потрібні файли вже є у проєкті.
3. Виконайте команди, замінивши `YOUR_USERNAME` своїм іменем користувача. Git може попросити налаштувати ваше ім’я й пошту для комітів.

```bash
git init -b main
git add .
git status --short
git commit -m "Add complete student response assessment application"
git remote add origin https://github.com/YOUR_USERNAME/osvitnii-protses.git
git push -u origin main
```

Авторизуйтеся у GitHub через налаштований Git Credential Manager або GitHub CLI. Після публікації перевірки з `.github/workflows/checks.yml` з’являться у вкладці **Actions**.

Для наступних змін:

```bash
git add .
git commit -m "Describe your change"
git push
```

Архів містить і приховані файли: `.github`, `.env.example`, `.gitignore`, `.dockerignore`, `.gitattributes`. Вони мають потрапити в репозиторій. Робочий `.env`, резервні копії БД, кеші, залежності та результати локальних тестів виключені правилами Git. Права на сторонні моделі й бібліотеки визначаються їхніми власними ліцензіями; нова ліцензія на ваш проєкт автоматично не призначалася.

## Запуск після клонування

Потрібні Git, Docker з Compose v2 і Python 3 для допоміжних скриптів. Сам застосунок запускається у контейнерах. Для першого завантаження образів і зафіксованої версії NLP-моделі потрібен інтернет; після підготовки аналіз працює локально.

```bash
git clone https://github.com/YOUR_USERNAME/osvitnii-protses.git
cd osvitnii-protses
python3 scripts/configure.py
docker compose up -d --build
docker compose exec -T api python -m scripts.seed_demo
docker compose ps -a
```

У Windows можна використовувати `py -3` замість `python3`. Скрипт створює `.env` з окремими випадковими паролями БД і демонстраційних акаунтів та постійним ключем сесій. Наявний `.env` він не перезаписує. Пароль входу чотирьох демоакаунтів — значення `DEMO_PASSWORD` у вашому `.env`.

Вебінтерфейс: http://127.0.0.1:8081. API: http://127.0.0.1:8081/api/docs. Порт БД для локальної розробки: `55433`. Ім’я Compose-проєкту — `osvitnii-protses-github`. Окремі порти, образи та томи дозволяють цій копії працювати поруч з початковою версією на порту 8080. Щоб змінити порти, відредагуйте `WEB_PORT`, `DB_PORT`, відповідний `DATABASE_URL` та `CORS_ORIGINS` у `.env`.

Після першого запуску `models` і `migrate` мають завершитися з кодом 0, `api` та `db` — бути healthy, `worker` і `web` — працювати. Прогрес підготовки моделей:

```bash
docker compose logs -f models worker
```

GitHub зберігає код і запускає CI. Для роботи FastAPI, PostgreSQL і NLP потрібен ваш комп’ютер або сервер із Docker; GitHub Pages не запускає цю серверну частину.

## Перенесення поточної бази без втрати даних

Разом із версією для GitHub підготовлено **окремий приватний архів локальних даних**. Він містить `database.dump`, копію поточного `.env`, контрольні суми та кількість рядків у таблицях. Цей архів зберігається поза папкою GitHub і не призначений для публікації. Дамп зберігає акаунти, хеші паролів, навчальні матеріали, подання, аналізи, рішення, варіації, налаштування й журнал аудиту.

Для відновлення використовуйте нову порожню БД, **до** звичайного запуску міграцій і seed:

```bash
python3 scripts/configure.py
docker compose up -d db
python3 scripts/data.py restore /absolute/path/to/database.dump
docker compose up -d --build
```

Дочекайтеся готовності БД перед restore. Скрипт відмовляється перезаписувати заповнену БД і вимагає зупинити API та воркер під час відновлення. Якщо `.env` уже створений, пропустіть configure. Якщо інша БД уже заповнена, збережіть її власну копію та виберіть нове `COMPOSE_PROJECT_NAME` і вільні порти для окремого середовища. Видаляти початкові томи не потрібно.

Після відновлення паролі наявних користувачів залишаються попередніми. Нове значення `DEMO_PASSWORD` не змінює їх. Увійдіть повторно, оскільки ключ сесій у новому `.env` інший. Початковий `.env` із приватного архіву збережений для довідки; його порти й назва середовища належать початковому запуску.

Для наступної резервної копії:

```bash
python3 scripts/data.py backup .local/backups/database.dump
```

Скрипт не перезаписує вже наявний файл. Ваги моделей зберігаються в окремому Docker-томі й завантажуються тим самим підготовчим сервісом, а не з репозиторію. Зупинка через `docker compose down` зберігає дані та модель. Параметр `-v` видаляє томи, тому для звичайної зупинки він не потрібен.

## Збережений функціонал і документація

| Складова | Вміст |
| --- | --- |
| Студент | Реєстрація, вхід, курси, завдання, надсилання відповідей, результати та історія |
| Викладач | Реєстрація, курси, питання, еталони, поняття, правила, ручна перевірка, варіації, звіти |
| Адміністратор | Користувачі, ролі, довідники, призначення, зарахування, NLP, аудит |
| Аналіз | Локальні Stanza й MPNet, черга, повторний аналіз, історія, пороги та ваги |
| Розробка | FastAPI, React/TypeScript, PostgreSQL/pgvector, Alembic, Docker, тести, GitHub Actions |
| Матеріали | Документація `docs`, презентація `docs/presentation`, інструкція `docs/manual` |

Ілюстрована DOCX-інструкція збережена без змін. Її скріншоти відтворюють початковий стенд на порту 8080 і його навчальні акаунти. У чистій GitHub-копії використовуйте порт 8081 і власний `DEMO_PASSWORD`; назви сторінок і порядок дій ті самі. Додаткові приклади зі скріншотів відтворюються при відновленні приватного дампа.
