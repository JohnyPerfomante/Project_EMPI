# Протокол перевірки

Перевірки виконано 6 листопада 2026 року на Apple M1 Pro з Docker Desktop. Стенд працював на PostgreSQL 16.14 із pgvector 0.8.2, локальному MPNet та українському Stanza. Alembic застосував міграції до `0004_embedding_jobs`. Команда `alembic check` підтвердила, що схема відповідає моделям.

| Набір | Результат | Покриття |
| --- | --- | --- |
| Pytest | 23 пройшли | Доступ і сесії, межі курсів, CRUD, черга, відновлення після збою, налаштування, варіації, правила NLP, окремий тест справжньої моделі |
| Vitest | 3 пройшли | Параметри фільтрів, заголовок запитів, формат помилок, оновлення сесії |
| Playwright | 4 пройшли | Питання → еталон → публікація → подання → аналіз → рішення → повторне використання варіації. Адміністрування, мобільна навігація та зведення викладача |
| Docker Compose | API, БД, воркер та веб працюють | Збірка образів, старт із порожньою базою, міграції, завантаження ваг, seed і браузерні тести |
| Резервна копія | Відновлено 50 демопитань | Перевірено `pg_dump` і `pg_restore` на окремій тимчасовій базі |
| Статичні перевірки | Ruff і збірка TypeScript/Vite пройшли | `npm audit` не виявив відомих вразливостей у встановленому npm-дереві |

Під час аналізу 25 демонстраційних подань у Docker час обробки воркером мав p95 **1,634 с** і максимум **1,709 с**. Вимір включає читання матеріалів, векторизацію, зіставлення й розрахунок результату. Він не охоплює очікування в черзі та час завантаження моделі.

Оцінювання NLP на 150 прикладах подано окремо в [NLP_EVALUATION.md](NLP_EVALUATION.md). Браузерні перевірки проходили у Chromium. Роботу в інших браузерах можна перевірити додатковими проєктами Playwright.

## Реєстрація облікових записів

7 листопада 2026 року перевірено реєстрацію студентів і викладачів на оновленому Docker-стенді. Пройшли 19 backend-тестів реєстрації та наявних бізнес-процесів, 10 тестів клієнтської валідації й API та 7 браузерних сценаріїв. Збірка TypeScript/Vite та Ruff пройшли успішно.

Перевірено створення обох ролей, повторний вхід, Argon2-хешування, нормалізацію пошти, відхилення дублікатів, перевірку паролів, обмеження частоти, CSRF і конкурентні запити. Нові користувачі отримують доступ до конкретних курсів після призначення. Браузерні тести перевіряють форму на мобільному екрані й повторний вхід після завершення сесії. Облікові записи, створені цими браузерними тестами, блокуються після перевірки.
