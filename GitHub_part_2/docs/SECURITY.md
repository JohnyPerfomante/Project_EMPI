# Доступ і захист даних

Доступ до API перевіряється за чинною серверною сесією і поточною роллю. Студент бачить власну історію й доступні питання. Викладач має доступ до призначених курсів. Адміністратор керує ролями, довідниками, групами, призначеннями, аудитом і системними параметрами. Блокування, зміна пароля або ролі відкликають сесії.

Публічна реєстрація приймає ролі студента й викладача. Новий користувач активний і отримує доступ до курсів після призначення або зарахування уповноваженим користувачем. Поля адміністративних повноважень відхиляються валідацією. Унікальність пошти захищена обмеженням PostgreSQL, зокрема при одночасних запитах. Створення запису й подія аудиту фіксуються однією транзакцією. Ліміти реєстрації діють у 10-хвилинних вікнах окремо від лімітів входу.

Паролі хешуються Argon2id. JWT має короткий строк і зберігається в HttpOnly cookie. Refresh-токен зберігається як SHA-256 від випадкового значення і ротується під час оновлення. Cookie мають `SameSite=Lax`. Виробнича конфігурація вимагає `COOKIE_SECURE=true`, явно перелічених origin та JWT-секрету від 32 символів. Заголовок `X-EMPI-Request: 1` потрібен для запитів, які змінюють стан. SQLAlchemy передає дані як параметри запиту. React екранує текст, Nginx обмежує розмір тіла й задає політику завантаження ресурсів. Ліміти входу діють за обліковим записом і мережевим клієнтом.

Для використання поза локальним середовищем застосуйте HTTPS на довіреному reverse proxy, закрийте порт БД і встановіть виробничі секрети в середовищі розгортання. Вкажіть в Uvicorn довірені адреси proxy, якщо використовується реальна IP-адреса клієнта для лімітів. Визначте дозволені мережі, правила доступу до резервних копій і строки зберігання навчальних даних згідно з політикою закладу.

Журнал аудиту містить ідентифікатори, дію й час. Зміст відповіді та секрети не записуються в журнал подій воркера. Демонстраційні облікові записи дозволені в режимі `development`.

## Резервна копія і відновлення

```bash
docker compose exec -T db pg_dump -U empi -Fc empi > empi.backup
docker compose exec -T db createdb -U empi empi_restore
docker compose exec -T db pg_restore -U empi -d empi_restore --no-owner < empi.backup
```

Зберігайте копію у сховищі з обмеженим доступом. Перед зміною цільового підключення перевірте міграції та кількість навчальних записів у відновленій окремій БД. Ваги з тому `models` можна повторно завантажити за зафіксованою версією.
